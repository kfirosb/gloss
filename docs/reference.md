# Gloss reference

This is the detailed behaviour reference. The short public introduction is the repository [README](../README.md).

## Mac desktop release

Future updates follow the [Mac release protocol](mac-release-protocol.md).

Version 0.5.0 adds voice dictation: a mic button in the composer (or ⌘⇧M) records speech and turns it into text in the session's write language, using an on-device whisper engine bundled with the app, so audio never leaves the Mac. The first press downloads the speech model (about 574 MB) into `~/.language-assistant/models`; after that dictation works offline. macOS asks for microphone access once. Building the installer from source now also needs `npm run build:whisper`. There is no schema change: saved data is unchanged and version 0.4.0 can still open it.

Version 0.4.0 renames the product to Gloss: the app bundle, window title, Dock name, DMG and About dialog now say Gloss, and the app ships the new Gloss icon. Saved data stays under `~/.language-assistant`, the Claude channel server keeps its `language-assistant` name, and the assistant panels inside the workspace keep their labels, so existing conversations, settings and channel setups continue to work. Sessions launched from the app regenerate their Claude channel configuration with the new executable path the next time they are prepared.

Version 0.3.5 fixes automatic session discovery for Claude Code installed through npm or Homebrew: those installs run as `claude.exe`, which the liveness check rejected, so open sessions never appeared in the sidebar. The check now accepts that name and reads the full process name from lsof.

Version 0.3.4 makes a Claude session's normal final message its answer in the app, exactly as for Codex: the terminal and the app show the same text, written once. The channel's reply tool is no longer required for answers and serves only as an optional interim status while the agent keeps working; the 0.3.3 rule that hid a turn's final text after a reply-tool call is removed. Sessions already open keep the old instructions until they are restarted.

Version 0.3.3 shows one answer per message: when an agent answers through the app, its closing terminal recap is no longer displayed as a second message, and the channel instructions tell agents to stop after replying. The Settings dialog is compact and left-to-right with Languages and Sessions sections, and the sidebar's "Find sessions by path" button is gone. The Mac bundle is now fully ad-hoc signed, so on another Mac a downloaded copy shows the normal "Apple could not verify" prompt (open it via System Settings > Privacy & Security > Open Anyway) instead of "damaged and can't be opened".

Version 0.3.2 makes the app re-adopt a "+" session whose terminal is still running in its private tmux after the app was restarted, so the terminal button comes back instead of the session staying marked as ended.

Version 0.3.1 fixes two issues found right after 0.3.0: a Git project is named after its main checkout even when only a worktree was connected, and deleting the worktree you are viewing switches the app to the main checkout instead of refusing.

Version 0.3.0 includes local `main` through `ebe5b72`: the folder-oriented sidebar (resize, reorder, collapse, hide and restore projects), Connect folder with computer-wide search, worktrees created, opened and deleted from the app (with the warn-and-decide delete dialog), plain folders with optional Git initialization, the compact conversation view as the default, and a version label with an About panel. Saved data gains one table (schema 22); version 0.2.0 cannot open the upgraded database, so keep the pre-upgrade backup if you may go back. Version 0.2.0 added background sessions, session tabs, language settings, terminal controls, folder selection, improved Codex session liveness and bundled tmux.

On Apple Silicon with macOS 13 or newer, open `Gloss-0.5.0-arm64.dmg`, drag Gloss into Applications, and launch it from the Dock or Spotlight. Quit an older running version before replacing it. The app bundles its runtime and starts its local server automatically; Codex/Claude still need to be installed and authenticated separately. File search also requires ripgrep (`rg`) on your PATH. Existing conversations remain under `~/.language-assistant`. This release is ad-hoc signed only (no Apple Developer ID) and is not notarized: on first launch of a downloaded copy, macOS says it cannot verify the app; choose Done, then System Settings > Privacy & Security > Open Anyway. If macOS instead calls the app "damaged", run `xattr -cr "/Applications/Gloss.app"` once in Terminal.

To reproduce the installer, use Node.js 24 or newer, run `npm ci`, `npm run build:tmux`, `npm run build:whisper`, then `npm run desktop:dmg -- --arm64`. The DMG is written to `release/`. `npm run desktop` runs the desktop app from source; `npm run desktop:install` builds and installs it locally. Claude channel setup remains experimental and requires its existing explicit setup and consent flow.

A local companion for discussing coding-agent work in Hebrew or another language. It keeps the language conversation separate from the coding session, shows translated coding messages, prepares an English instruction for review, and delivers only after an explicit destination-specific Send action.

The core is independent of Superset. Claude Code 2.1.273 and Codex 0.154.0, 0.157.1 and 0.158.0 are the verified macOS adapter versions; they use the accounts already authenticated in those tools and do not require a separate provider API key. The adapters are version-gated and fail closed when their local protocol changes.

Install with Node.js 24 and `npm ci`. Build with `npm run build`. The local launcher is available through the compiled CLI:

```sh
node dist/server/runtime/cli.js --agent codex --session "$CODEX_THREAD_ID" --language he --project "$PWD"
```

It prints an authenticated loopback URL and keeps the service in the foreground for now. The browser UI uses the capability in the URL fragment; it never sends that capability in a query string. The installed Superset 1.17.0 CLI cannot create an embedded browser pane automatically, so open the printed URL manually in Superset's embedded browser. The Superset host can return to a specific workspace/tab/pane when those identifiers are supplied; it does not inject terminal keys or alter native permissions.

Claude's launcher skill is `integrations/claude/language/SKILL.md` and is invoked as `/language hebrew`. Codex's skill is `integrations/codex/language/SKILL.md`; Codex's native spelling is `$language hebrew` or `/skills`. Both resolve to the same local application workflow.

Product history is stored under `~/.language-assistant/state.db` with restrictive local permissions. Delete a conversation through the application to remove its product messages, drafts, receipts, and cached translations. Native Claude/Codex transcripts remain owned by their tools. Reconnecting requires the original exact session to remain available; an ambiguous or missing session is shown for selection rather than guessed.

The language model is an economical model in the same tool ecosystem (`haiku` for Claude, `gpt-5.6-sol` for Codex by default in this account). Availability and usage limits come from the existing account. Native approval prompts stay in the coding tool and are never answered by the assistant.

## Live terminal bridge

The launcher starts the panel HTTP server first and automatically gives the native session adapter its loopback endpoint and capability. No bridge flags are needed for the normal local workflow. The adapter posts completed assistant replies to `POST /api/source/messages`; Codex commentary, reasoning, and tool output are excluded. English terminal replies are translated inside the panel.

The exact native session ID is required. Conversations are stored separately per agent/session. On reconnect the adapter pages through native history in source order and retries failed HTTP delivery. Stable native message IDs suppress duplicates; messages, translations, timestamps, and the recovery cursor survive a restart. Newer translations have priority over history backfill. The browser reconnects dropped event streams automatically.

For diagnosis the launcher writes `source-delivered` records with session/message IDs and sequences, never message text or capabilities. The URL printed at startup is the authenticated panel link. After a restart use that new link, or keep `LANGUAGE_PANEL_CAPABILITY` set to the same locally generated secret and use `--port` to preserve the panel address.

The optional `--bridge-endpoint` and `--bridge-capability` flags are for a separately hosted panel. They are not required for local use.

## Folders and worktrees

**Connect folder** adds any folder as a project, found by computer-wide search, by typing its full path (`/…` or `~/…`), or with **Browse folders** (in the Mac app only); connected folders are stored by the local server and survive restarts. The sidebar can be resized, projects can be reordered, collapsed, hidden and restored, and the running version appears beside Settings with an About panel. Plain folders work without Git; **Initialize Git** is optional and makes no commit. A Git project can create a worktree, by default at `<project>/.worktrees/<name>` (a per-project location is remembered). `/.worktrees/` is added once to the root `.gitignore` only when the location is inside the project (a custom inside location adds its own relative path); a location outside the project adds nothing. A repository with no commits cannot host a worktree. Deleting a worktree is never blocked by unsaved changes: the dialog shows modified and untracked counts, oldest and newest change times, unmerged commits, the open sessions started from Language Assistant that will be ended, and any other open sessions in the folder that keep running, with an optional **Ask the agent about these changes** summary, and you decide. The branch is kept, and conversations are kept unless you tick the checkbox to delete them; kept conversations stay reachable from Hidden projects → Missing folders → **Show sessions**.

## Reading and resizing

The permanent **Sessions** sidebar groups native Claude/Codex sessions by project or workspace folder. It updates automatically without changing your selected destination. Open sessions show their observed Working/Idle state and an active green dot; closed sessions move to **Saved**. Native session titles appear when the provider exposes them; otherwise the workspace/provider/short session ID remains available. Unknown or stale discovery is labeled rather than shown as Idle. Collapse the sidebar to an icon rail; on narrow screens it opens as an overlay. See Folders and worktrees above for connected folders.

**Minimize Assistant** hides the language discussion while retaining Live Conversation, the input, attachments, and Send to Terminal. **Show full Assistant** restores the previous layout and conversation. Display mode is remembered per session in this browser; drafts, reviews and routing remain in the existing session workspace. Enter reopens the discussion, Shift+Enter inserts a newline, and Send does not change display mode. If browser storage is blocked, controls still work in memory.

Completed assistant responses offer **Summarize in Hebrew**. This is an on-demand reading aid using the configured language backend, never a terminal instruction. A labeled Hebrew card appears above the collapsed response; **Show full response** / **Show summary** switch views, and Original remains accessible. Loading or failure leaves full text visible, with retry on error. Successful summaries are cached separately by session, source content, model and prompt version. Changed content invalidates the displayed summary. Responses above 160,000 characters or generated summaries above 4,000 characters are rejected explicitly. New interrupted responses cannot be summarized; legacy nonempty discussion replies are treated as completed because older storage did not record completion.

Drag the border between panes using the double-headed arrow in its center. On desktop the main divider moves left/right; on narrow windows it moves up/down. Drag the boundary above the composer up/down to change the Language Assistant and composer heights. Sizes are saved per session, with minimum sizes to keep controls accessible. Focus a divider and use arrow keys for keyboard resizing; double-click resets its split. **Expand** opens a full-window reading view; **Restore** or Escape returns to the workspace.

Messages and prepared instructions support Markdown headings, bold, lists, quotes, links, tables, fenced code blocks, and `==highlighted text==`. Code blocks retain left-to-right formatting, scroll independently, and offer **Copy code**. Raw HTML is not rendered.

Hebrew prose uses natural phrasing while keeping English product labels and professional terms (such as Queue, Live Conversation, Language Assistant, Markdown, code blocks, Copy code, layout, and refresh). The policy applies to translations, discussion replies, and localized draft previews. Instructions delivered to coding agents remain in English.

## Reviewing and sending instructions

Live Conversation and Language Assistant show the latest message by default; **History** reveals earlier messages in original order. Select user and assistant messages with **Add to answer**. **Prepare instruction** combines them in conversation order and opens a large, editable Hebrew review. A corresponding concise English instruction preserves the same requirements but remains hidden.

**Send to Codex** (or **Send to Claude Code**) in the pop-up approves and sends directly. Hebrew edits regenerate the matching English before delivery. There is no Queue or separate approval step. Confirmed **Sent** closes the review, removes the prepared instruction, and resets its selections. A successful Claude channel handoff also completes the review immediately, while the app separately waits for Claude's response. Other queued, failed, blocked, or unconfirmed deliveries preserve the review and edits. Unresolved delivery cannot be resent or replaced.

The X closes the pop-up without deleting anything; **Resume review** restores it. Prepared instructions persist on the server, and local edits and selections survive browser refresh. Preparing a replacement requires explicit confirmation. Destination appears once at the top. Enter in the discussion composer continues discussion and never sends an agent instruction.

For Claude's experimental channel, a successful handoff clears the submitted composer text and attachments and shows **Waiting for Claude’s response**. You can start another draft immediately; sending still respects Claude's busy/approval state. The handoff does not claim Claude has read or answered the message. Matching replies continue to be tracked across reloads, and a late reply never clears a newer draft. An uncertain handoff preserves the draft and the **Check delivery** / **Release composer** controls; neither action resends the message.

**Send to Codex in English** beside the composer translates only the current composer text and sends it directly, without selections, a review pop-up, or additional approval. It does not modify the prepared instruction or selected messages. Confirmed Sent clears only the submitted text; newer edits are preserved. Failed delivery allows an explicit retry. Queued or uncertain delivery is checked automatically in the background using a status-only endpoint that cannot send. The composer shows only **Send to Codex in English**, with no Ready label or manual delivery-check action. Blocked delivery retains the text until the agent is available. Composer text and request identity survive refresh.

Click the selection count (for example, **2 selected**) to review selected messages in conversation order. **Deselect** removes one message; **Clear all selected** removes all selections immediately. These controls never replace or modify an already prepared instruction.

The replacement confirmation shows the current selected messages, not the old answer. The new prepared review opens only after preparation succeeds; the previous instruction remains safe if preparation fails.

All three panels are movable: Live Conversation, Language Assistant, and Chat with the Language Assistant. Drag the dotted move handle onto another panel to swap them, or click it for a swap menu. Choose Split, Columns, Rows, or Chat across bottom in Layout; resize their borders or Expand any panel, including the composer. Order, layout, and sizes persist in each session workspace on the local server, with browser recovery for unsaved edits. Reset layout restores the default arrangement without clearing your text, selections, or prepared instruction. Chat across bottom puts the composer across the full bottom width with the two conversations above it and a draggable height divider. Narrow screens stack panels in the chosen order.

**Reset instruction** clears the prepared instruction and its review edits, while retaining composer text and selected messages. Confirm the reset, then use Prepare instruction again for a fresh answer. Reset never cancels, repeats, or removes the record of an already submitted delivery; its later receipt cannot clear a newer instruction. Failed resets preserve the existing review.

## Dictation

The mic button in the composer records speech and turns it into text on your Mac, in the session's write language (Hebrew or English). Press it (or ⌘⇧M), talk, and text arrives in the composer after each short pause (about half a second) or about every 8 seconds if you keep talking; press again or Escape to stop. Enter while recording stops the mic, waits for the last words, and sends. The first press downloads the speech model (about 574 MB) into `~/.language-assistant/models` and keeps it across versions; after that dictation is fully offline and audio never leaves the computer. macOS asks for microphone access once per installed app bundle; if you deny it, enable Gloss under System Settings → Privacy & Security → Microphone. Nothing speech-related runs until you press the button, and the engine frees its memory after three minutes without use. A recording stops by itself after 10 minutes. Running from source needs `npm run build:whisper` once; without it the button is disabled with "speech engine not built". After building it, restart the running server; the button enables once the server starts again. In a browser rather than the Mac app, the browser may claim ⌘⇧M for itself, so use the button.

## Sessions and workspace recovery

Use **Choose destination** in the compact header to open the session picker. The header summarizes the selected project, branch/worktree, coding agent and activity. Open sessions are grouped by canonical Git repository identity, so linked worktrees appear together; ordinary folders are grouped by canonical folder path. Same-name projects remain separate and show parent-path hints. Rows abbreviate native session IDs; **Session details** exposes the full ID and paths.

On macOS, the panel automatically discovers open interactive Codex CLI user sessions from the configured Codex home. It scans immediately and every two seconds without overlapping scans, then connects supported destinations without manual discovery or refresh. Under healthy local conditions, a row is expected within five seconds after Codex creates the native session. Starting the terminal and creating that session can take additional time; slow ownership probes or large session inventories can also delay discovery. Newly discovered sessions never replace your current selection or unsent work. Discovery sends no instruction. Connected sessions can capture and translate native history and new replies through the existing bridge.

Automatic discovery depends on Codex's native writer-lock ownership and SQLite metadata, including authoritative session-origin fields. Support is pinned to the verified Codex versions 0.154.0, 0.157.1 and 0.158.0; other versions are not implicitly supported. Internal workers, subagents and noninteractive exec workers, including Language Assistant workers, are excluded. Unverified origins or failed scans show a discovery limitation rather than guessing which sessions are open; discovery health is separate from each row's activity. Unsupported CLI versions can appear with an explanation but cannot be selected as a delivery destination. Automatic discovery is currently Codex-only and macOS-only; it does not automatically enumerate Claude sessions or unverified editor/app-server origins. Daemon-backed Codex TUI sessions are included when their native origin is verified.

Once native closure is verified, registered sessions move under **Saved**, where their saved work can be opened. A daemon-backed session can remain open after its terminal closes until Codex releases the native thread; there is no verified upper bound for that delay. Missing projects retain their saved work and show an unavailable status. A selected session closing does not select another destination. **Connect folder** inside the picker retains manual discovery and exact-target registration, including Claude sessions. Manually connected Claude sessions show their working/idle status and move to Saved when disconnected. **Reconnect same target** is offered for a selected disconnected registered session and never substitutes another native destination. Tab and Enter navigate/select destinations; Escape closes the picker and returns focus to the header. The picker scrolls within narrow or short windows.

Each session owns its conversation, composer, attached files, selections, review edits, layout and file numbering. The active choice belongs to each browser tab. Hidden registered sessions continue capturing native updates. Switching, refreshing or restarting the panel does not resend uncertain deliveries. A queued receipt is not proof that the native agent accepted or answered the instruction: the panel waits for native acceptance and captures completed assistant replies separately.

Workspace saves use revision checks. When two tabs edit the same session, a conflict keeps the losing local edits for explicit resolution instead of overwriting them. Browser storage failure still permits server saves; unsaved recovery depends on available browser storage. Web Locks distinguish copied/opener tabs where supported; without Web Locks, a copied/opener tab can share its original tab's browser recovery identity, so independent unsaved recovery is not guaranteed. Saved server workspaces remain available.

Existing conversation IDs and prepared work survive schema migration. Legacy global layout settings are adopted only by the launch session; another session starts with its default layout. Existing launch URLs need no session selector. Compatibility API routes stay pinned to the launch session; new workspace, file, action and event routes are session-scoped.

## File and image references

Drop individual files into the composer, choose **Attach files**, or paste an image. On macOS, Control+Command+Shift+4 copies a screenshot for pasting; Command+Shift+4 saves a file to attach. Open **Files** for a collapsible sidebar scoped to the selected session's project/worktree. Expand nested folders in the compact file tree or search by filename/content. Folder expansion stays in place while browsing. Click a file, or choose an **@** result with the mouse or arrow keys and Enter, to open a read-only preview. Browsing never attaches a file or allocates a number. **Attach file** in the preview, or drag a sidebar file into the composer, adds the file and its stable **@File N**/**@Image N** text reference without sending. Repeated attachment keeps one membership and one reference token. Unresolved mentions remain ordinary text. Escape closes the picker.

Markdown and HTML open in rendered **Preview** mode with a **Source** tab. Clicking a local file link in a conversation reveals it in Files and opens the preview popup instead of a new browser tab. HTML previews render with native video and audio controls; relative media paths resolve beside the HTML file, and direct HTTP(S) media URLs can play. Local media previews support up to 128 MiB combined per HTML preview. Scripts, embedded web players, and forms remain disabled. In text-file previews, **TL;DR** generates a brief Hebrew summary and **Translate** generates a full Hebrew translation; **Show original** restores the file. Review reads the full UTF-8 file (up to 160,000 characters), not just the displayed prefix, and asks you to reopen the preview if the file changed. Code and JSON use basic syntax highlighting and line numbers; long lines scroll within the preview. Other readable text uses a plain source view, images fit the preview, and unsupported formats show a fallback while remaining attachable.

Uploads are managed local copies. Worktree references point to the live file and read its current contents when used; they are not snapshots. Search respects ignore rules and excludes `.git`, `node_modules`, `dist` and `build`; manual folder browsing can show hidden/generated entries. Folder pages contain up to 100 entries (2-second scan and 100,000-entry ceiling); filename inventory is bounded to 10,000 candidates, 2 MiB and 3 seconds. Search returns up to 50 matches; content search checks up to 200 files and their first 128 KiB within 2 seconds. Partial results and skipped/unreadable files are indicated. Text previews retain the first 128 KiB, with truncation marked; safe PNG/JPEG/WebP/GIF previews are limited to 4 MiB. Binary/invalid UTF-8 and oversized image previews show their unavailable state. Internal file cards and previews show relative paths; uploaded copies never present managed storage as an original location. Files outside the registered canonical root, escaping symlinks, missing files and folders are rejected. A reference that becomes unavailable stays visible with an error instead of silently disappearing.

Each session has separate **File 1**, **File 2** and **Image 1**, **Image 2** counters. Removing an attachment from the composer does not reuse its number or delete its uploaded bytes. Historical attachments remain with their original exchange; they are not carried into unrelated replies. Selecting a message for **Prepare instruction** carries its references into the editable review once each.

The composer accepts up to 10 attachments, including at most four images, with a 10 MB limit per upload. Supported images are PNG, JPEG, WebP and GIF. Language operations read UTF-8 text with a combined 160,000-character budget; oversized text is rejected rather than truncated. Binary and invalid UTF-8 content is marked unreadable while its reference remains available. There is no recursive folder upload, general-purpose document conversion, cloud synchronization or shared-team workspace.

Enter discusses the text and references with the Language Assistant. **Send to Codex in English** translates the current text and sends a deterministic manifest of numbered local paths and the worktree identity, asking Codex to read files and inspect images. Image-only sends are supported. Codex CLI 0.154.0 does not accept native images in its queue interface, so coding-session image delivery uses local paths; Codex language workers receive native image inputs. Claude language workers can discuss images using image content blocks, but the current Claude coding-session peer adapter does not support file or image delivery and preserves the instruction with an explanatory error.

Pending and failed work retains its text and attachments. Confirmed Sent clears only the submitted content in the originating session, preserving newer edits and references. A prepared review and a direct composer send keep separate identities. No uncertain delivery is automatically resent.

## Verification

Run `npm run typecheck`, `npm test`, `npm run test:e2e -- --workers=1`, `npm run build` and `git diff --check`. A single browser worker avoids timing stalls observed on this host. Automated suites cover schema 13 migration, native-origin classification, canonical repository grouping, non-overlapping discovery and stale-scan recovery, catalog ordering/restarts, compact picker accessibility and focus, discovery without workspace replacement, two-session restart and source replay, receipt reconciliation without resending, per-session numbering, upload/worktree references, scoped cleanup, independent tab selection, copied-tab recovery, storage failure and revision conflicts. Native acceptance and completed replies require separate live checks; routed browser fixtures and fake adapters do not establish those results.
